# Storage and the Tauri integration

The views take values and give back values; they never read or write files
(decision 7). Keeping a view's data is the host's, through a **storage
adapter** (decision 9): `@eisenhower/model` defines the interface and ships
two adapters, and in a Tauri 2 app the native side comes from
[`tauri-plugin-eisenhower`](../../crates/tauri-plugin/README.md) and its
typed client [`@eisenhower/tauri`](../../packages/tauri/README.md), which
adds a third:

- **Documents** are text: JSON, two-space indented, ending with a new line.
- **Revisions** guard every save: a save quoting the revision it read is
  refused when the stored document changed since, so one window or program
  never overwrites another's work unseen. Every built-in adapter uses the
  same revision, the SHA-256 of the text's UTF-8 in lower-case hexadecimal
  (`textRevision`), so a revision means the same in each.
- **On disk**, the plugin reads a document with its hash and writes it in
  one rename, refused when the file changed on disk since it was read (the
  hash guard, as Donizetti and jerome guard their files; decision 10).

## Documents and adapters

A stored document is `{ format: "eisenhower", kind, version, data }`, where
`kind` is `board`, `timeline`, `gantt` or `todo` and `version` the version
of that kind's data. `loadDocument` and `saveDocument` read and write one
through any adapter, by key:

```ts
import { loadDocument, saveDocument, StorageError } from "@eisenhower/model";

const loaded = await loadDocument(storage, key, kind); // null when there is nothing under the key
let revision = loaded?.revision;
// kind is the view's DocumentKind; … <Board value={data} onChange={…} />
try {
  revision = await saveDocument(storage, key, kind, data, revision);
} catch (error) {
  if (error instanceof StorageError && error.problem === "changed") {
    // Changed elsewhere since it was read: ask the user, then save again without the revision to overwrite.
  }
}
```

`loadDocument` throws a `DocumentError` (`notJson`, `notEisenhower`,
`wrongKind`, `newerVersion`, `invalid`) for a text that is not a valid
document of the kind; a document is never half loaded. Both throw a
`StorageError` when the storage fails, with its `problem`:

| Problem | When |
| --- | --- |
| `changed` | A save quoted a revision and the stored text is no longer that one (or is gone); nothing was written |
| `readFailed` | The text could not be read |
| `writeFailed` | The text could not be written; what was stored is as it was |
| `unavailable` | The storage cannot be used at all (no `localStorage`) |

Its `key` says which document, `detail` is the system's own words, for logs,
never interface text, and `cause` is the underlying error.

The adapters, each a `StorageAdapter` (`read(key)` → `{ text, revision }` or
null; `write(key, text, expectedRevision?)` → the new revision):

| Adapter | From | Keys | Keeps documents |
| --- | --- | --- | --- |
| `memoryStorage(initial?)` | `@eisenhower/model` | any string | as long as the page: tests, demos, documents a host keeps elsewhere |
| `localStorageAdapter(prefix?, storage?)` | `@eisenhower/model` | any string, stored under `prefix` (`eisenhower:` by default) | in the browser's `localStorage`, between visits; another tab's write is caught by the revision |
| `tauriStorage()` | `@eisenhower/tauri` | file paths | in files on disk, through the plugin |

A host may write its own adapter (a database, a server): it answers null for
a key with nothing under it, and refuses a write quoting a revision the
stored text no longer has with `new StorageError("changed", key)`.

## Registering the plugin

In the app's `Cargo.toml`, by git (pinned to a commit) or by path
(decision 11):

```toml
tauri-plugin-eisenhower = { git = "https://github.com/Federiker/eisenhower", rev = "<commit>" }
```

then in the app's builder (`src-tauri/src/lib.rs`):

```rust
tauri::Builder::default()
    .plugin(tauri_plugin_eisenhower::init())
```

The plugin keeps no state and needs no setup. The window's capability
(`src-tauri/capabilities/*.json`) allows its commands:

```json
{ "permissions": ["core:default", "eisenhower:default"] }
```

`eisenhower:default` allows every command; each also has its own
`eisenhower:allow-<command>` and `eisenhower:deny-<command>` (for example
`eisenhower:allow-read-document`), listed in
[the generated reference](../../crates/tauri-plugin/permissions/autogenerated/reference.md).
The commands take any path the window passes, as Tauri's own file plugin
does without a scope: the capability is the boundary, so grant it only to
the app's own windows. A host usually asks for the path with a dialog (for
example `@tauri-apps/plugin-dialog`'s `open` and `save`).

In the app's TypeScript, `@eisenhower/tauri` (with `@tauri-apps/api`) gives
the adapter, or the commands themselves:

```ts
import { loadDocument, saveDocument } from "@eisenhower/model";
import { readDocument, tauriStorage, writeDocument } from "@eisenhower/tauri";

const storage = tauriStorage();
const loaded = await loadDocument(storage, path, kind);
// … and later
const revision = await saveDocument(storage, path, kind, data, loaded?.revision);

// Or the commands, for a host that handles the text itself:
const file = await readDocument(path); // { text, hash } or null
const hash = await writeDocument({ path, text, expectedHash: file?.hash });
```

## Commands

Each command is `plugin:eisenhower|<command>`; the client's function is
given in brackets. Both run on a blocking thread. Arguments and answers are
plain JSON: documents are text, so they need none of the raw binary bodies
Donizetti uses for its scores.

| Command | Takes | Answers |
| --- | --- | --- |
| `read_document` (`readDocument(path)`) | `path` | `{ text, hash }`, or null when there is no file |
| `write_document` (`writeDocument({ path, text, expectedHash? })`) | `path`, `text`, `expectedHash` (optional) | the new hash |

### The hash guard

The hash is SHA-256 of the file's bytes in lower-case hexadecimal (64
characters). A document's bytes are its text's UTF-8, so the hash is
`textRevision(text)`, and `tauriStorage` uses it as the revision.

- `read_document` answers null for a path with no file (nor folder), so a
  document not saved yet is not a failure; a file that is not UTF-8 text is
  refused with `not_text`, and any other failure (no permission, a folder at
  that path) is `read_failed`.
- `write_document` writes the text to a temporary file in the document's
  folder (`.<name>.<random>.tmp`), flushes it to disk, then renames it over
  the document: the file on disk is always the old document or the new one.
  On macOS and Linux a replaced file keeps its permissions.
- The folder must exist: a save never creates folders, so a path whose
  folder has gone (a removed drive, a renamed folder) fails with
  `write_failed` rather than writing somewhere the user did not choose.
- With an expected hash (the one `readDocument` or the last `writeDocument`
  gave), the file must still be the one the app read. It is checked before
  writing and again just before the rename; if another program changed it,
  nothing is written and the save fails with `changed_on_disk`, with both
  hashes. A file that is no longer there has changed too (`actualHash` is
  null), whatever hash was quoted. Without an expected hash (a new file,
  Save As, or the user choosing to overwrite) the file is written whatever
  is there.
- An empty path is refused with `invalid_request`. A relative path is taken
  from the app's working folder, which a host rarely means: pass absolute
  paths, as the file dialogues give them.

## Errors

Every failure reaches the app as `{ code, params }`, never English text; the
client throws it as an `EisenhowerPluginError` with `code` and `params`
(`pluginErrorCodes` lists the plugin's codes). `detail` is the operating
system's own words, for logs, not for the interface.

| Code | When | `params` |
| --- | --- | --- |
| `read_failed` | A document could not be read (or checked before a save) | `path`, `detail` |
| `not_text` | The file is not UTF-8 text | `path` |
| `write_failed` | A document could not be written, or its folder does not exist; the file is as it was | `path`, `detail` |
| `changed_on_disk` | The file is not the one the app read, or is gone; nothing was written | `path`, `expectedHash`, `actualHash` (null when gone) |
| `invalid_request` | An empty path | `detail` |
| `internal` | The command's thread stopped | `detail` |

The client adds two of its own: `invalid_response` (the plugin answered
something of the wrong shape; `command`, `detail`) and `unknown` (the call
failed in a way that is not the plugin's, such as a command the capability
does not allow, or no Tauri at all; `detail` is the text). An answer of the
wrong shape is an error, never a substitute value.

`tauriStorage` turns them into `StorageError`s: `changed_on_disk` becomes
`changed`; anything else becomes `readFailed` from `read` and `writeFailed`
from `write` (a `read_failed` while checking a save is a `writeFailed`),
with the plugin's `detail` (or the error's message) as `detail` and the
`EisenhowerPluginError` as `cause`, for a host that wants the code.
